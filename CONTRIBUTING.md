# Working on Halo

Halo is a dependency-free web app: plain HTML, CSS and JavaScript with no framework and no build step
required to run it. This guide covers how the code is organized and the design rules every screen follows.

## Run it

- Open `src/index.html` in a browser while developing. Every file loads individually, so edits show on refresh.
- `python3 tools/build.py` bundles everything (fonts included) into one self-contained `index.html`
  at the repo root, which is what GitHub Pages serves. It also writes `dist/halo-artifact.html`.
- `node tools/preview.mjs '#/digest' out.png 1440 900 dark` renders a screenshot of any route
  (needs Playwright). Add `390 844` for phone size.
- `node tools/e2e.mjs <folder-with-built-index> <out-folder>` walks the whole product from a clean first run.

## Architecture

| Layer | Files | What it does |
| --- | --- | --- |
| Utilities | `src/js/core/util.js` | Escaping, formatting, the demo clock, three-point estimates, storage, the confirmation chime |
| Icons and logos | `icons.js`, `brands.js` | Halo's icon set (24 px grid, 1.5 stroke) and simplified connector marks |
| Rendering | `morph.js`, `ui.js` | DOM morphing, markup helpers, overlays, menus, tooltips, toasts |
| Data | `data.js`, `store.js` | The fictional Brightwater workspace, selectors (`H.q`) and actions (`H.act`) |
| AI | `ai.js` | Provider chain (proxy, visitor key, Claude artifact runtime, scripted demo) |
| App | `app.js`, `shell/*` | Router, render loop, keyboard shortcuts, sidebar, command palette, quick add, tour |
| Screens | `src/js/screens/*` | One file per area, each registering `H.screens.<name>` |

Rendering is declarative. A screen returns an HTML string, state changes go through `H.store.commit`
or an `H.act` action, and the DOM is morphed rather than replaced, so focus, scroll and input survive.
Clicks use `data-action`, navigation uses `href="#/…"` or `data-nav`, and fields use `data-input`,
`data-change` and `data-enter`. All stored times are minute offsets from the demo clock (`H.now()`),
so the workspace reads coherently on any day it is opened.

## Design rules

- Tokens only. Colors, type, radii and motion come from `src/styles/tokens.css`, generated by
  `tools/brand/tokens.py`. Every screen must work in light and dark.
- Calm hierarchy: one primary action per view, sentence case, generous spacing on a 4 px grid.
- Signal orange is rare and meaningful: attention counts, the mark, progress, live states, focus rings,
  urgent priority. Primary buttons are ink, never orange.
- Priority markers are squares. Status uses the status glyphs. No gradients, glows or heavy shadows.
- Shallow navigation: detail views are one level deep with breadcrumbs.
- Copy is plain, warm and first person where Halo speaks for someone. No exclamation marks, no emojis.
- Every control does something real, destructive actions offer Undo, and empty and error states exist.
- Accessibility: real buttons, labeled icon buttons, visible focus, keyboard reachable, WCAG 2.2 AA contrast,
  and reduced motion respected.

## Brand, film and proxy

- Brand system: `tools/brand/` regenerates logos, icons, tokens, social images and the guidelines PDF.
- Film: `film/src/film.html` is a deterministic timeline; `node tools/film/render.mjs wide film/halo-launch-film.mp4`
  renders it with ffmpeg.
- Live AI proxy: see `worker/README.md`.
